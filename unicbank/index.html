UNIC Bank

Reduced time-to-value in mobile banking — a UX/UI redesign of the registration, account-opening and transfer flows for a B2C fintech concept.

Role
UX/UI Designer
Type
B2C fintech concept
Platform
iOS mobile app
Duration
4 weeks

Challenge

Progressively unlock useful banking functionality. The product had to support:

  • Registration and bank account opening
  • UNIC Bank cards and third-party card management
  • Domestic and international transfers

What had to be different: reduce time to first value. Competing apps front-load setup before users can do anything useful. UNIC needed to reverse that order without making the product feel incomplete.

Scope: Competitor analysis · User interviews · Hypothesis validation · UX flows · UI design · Interactive prototype · Developer handoff

Interviews

Confirmed 3 hypotheses. Users struggled most with long sign-up and unclear onboarding, were concerned about unintended scheduled transfers, and preferred access to recent transactions over recent recipients.

HypothesisResultNote
Split registration and bank account opening Confirmed Users wanted to explore before giving full KYC data.
Home screen as progressive onboarding Confirmed Users needed clearer guidance after registration.
Scheduled transfers with confirmation control Confirmed · Insight Users wanted automation without silent money movement.
Quick transfers to recent recipients Not confirmed Recent transaction history mattered more than quick access to recipients alone.

AI in the loop

  1. Hypothesis refinementHelped sharpen each opportunity into a specific assumption to validate in interviews.
  2. Question checkChecked questions for bias and assumptions using The Mom Test principles.
  3. Transcript structuringTranscribed Zoom calls and grouped answers by question.
  4. Evidence taggingTagged responses as strong, weak or no support for each hypothesis.

Decision 01

Split registration from bank account opening. The user can sign up, browse and use lightweight features without committing to a full KYC flow up front. Account opening becomes contextual.

Before~10 min to value

  1. Sign up
  2. ID verification
  3. Address proof
  4. Account opening
  5. First useful action

After~3 min to value

  1. Short registration
  2. Guided home screen
  3. First useful action
  4. Account opening later

Decision 02

Home screen as progressive onboarding. The home screen is a dashboard and a discovery layer at the same time. It surfaces the next meaningful action based on what the user has already done.

Decision 03

Scheduled transfers with confirmation. Users can choose to receive a confirmation notification before each scheduled transfer is executed. Automation stays convenient, while users remain in control.

Concept outcomes

  1. Registration became a lightweight entryFull KYC moved from the first step to the moment when account opening became relevant.
  2. Home screen became a guided starting pointThe first home screen explained available actions instead of showing a passive empty state.
  3. Scheduled transfers gained confirmation controlUsers could keep recurring payments convenient without allowing money to move silently.
  4. Recent recipients were deprioritizedTesting showed stronger interest in recent transactions than quick access to recent recipients.

Prototype validation

~10 min → ~3 min

Time to first useful interaction. Estimated from the prototype flow.

  • Next-action clarity: Users understood what to do next from the first home screen.
  • Account-opening timing: Users recognized full account opening as a contextual next step, not an upfront blocker.
  • Transfer confirmation clarity: Users understood that scheduled transfers would not be sent without confirmation.
